# Генерация биомов и жил

Текущая реализация соответствует спеке `Генерация_биомов_и_жил_v2.md`: ландшафт и ресурсные пятна — две независимые фазы. Ниже — как это работает в коде сейчас.

Источники: спека v2, `docs/vault` (`WorldBiomeMap`, `WorldResourceScatterer`, `ResourceNode`) и `Assets/Script/Core/World/`.

Жилы **не пишутся в сейв**. При каждом входе в мир карта и жилы собираются заново из **сида мира**. Постройки остаются; экстракторы после рассеивания заново биндятся на клетку.

---

## 1. Конвейер при загрузке мира

```
MainMenu → LoadingScreen
  1. сцена SampleScene
  2. GridSystem.Awake вешает WorldBiomeMap + WorldResourceScatterer
  3. WorldBiomeMap.Awake: seed из WorldCatalog.Active → Generate()
  4. WorldResourceScatterer.Start → Scatter() (корутина, ScatterProgress)
  5. SaveSystem поднимает здания / игрока
  6. экстракторы биндятся на ResourceNode в своей клетке
```

Тест без новой игры (только Play): меню Unity **Walk of Industry → Regen Map (Keep Extractor Veins)**. Новый seed биомов и жил; жила под экстрактором и соседние ноды того же типа остаются.

RNG жил: `new System.Random(map.seed * 31 + 9)`. Сид мира задаётся при создании (`WorldCatalog.CreateWorld`, `Random.Range(1, 999999)`).

## 2. Сетка и размер карты

| Что | Сейчас |
|---|---|
| Клетка | 1 м (`GridSystem.cellSize`) |
| Источник границ | Unity Terrain в сцене (часто **выключен**) |
| Типичный Terrain | ~1000 × 1000 м, высота 600, heightmap 513 |
| Игровая карта | клетки покрытия terrain (`width` × `height`, минимум 8×8) |
| Картинка земли | квад `BiomeOverlay` чуть шире карты (~**280 м** за край) |

Игрок видит не heightmap, а runtime-квад с текстурой биомов (шейдер `WalkToBiomeUnlit`). За краем игровой площади `Get` возвращает **океан**.

Клетка `(x, z)` в массиве биомов = мировая клетка `(minX + x, minZ + z)`.

## 3. Какие биомы есть

Перечисление `WorldBiome` в `WorldBiomeMap.cs`. Восемь значений.

| Биом | Enum | Цвет на карте / земле | Ходить | Строить | Жилы | Амбиент |
|---|---|---|---|---|---|---|
| Поле | `Field` | светло-зелёный `0.58, 0.74, 0.34` | да | да | нет | `amb_field` |
| Редколесье | `Woodland` | средне-зелёный `0.30, 0.50, 0.24` | да | да | деревья | `amb_forest` |
| Лес | `Forest` | тёмно-зелёный `0.13, 0.30, 0.16` | да | да | деревья | `amb_forest` |
| Пляж | `Beach` | песочный `0.86, 0.74, 0.42` | да | да | песок | `amb_water` |
| Озеро | `Lake` | голубой `0.30, 0.62, 0.76` | **да** | нет (кроме насоса) | нет | `amb_water` |
| Океан | `Ocean` | синий `0.11, 0.32, 0.52` | **нет** | нет (кроме насоса) | нет | `amb_water` |
| Вершина | `MountainPeak` | тёмно-серый `0.28, 0.28, 0.30` | да | да | руды | `amb_mountain` |
| Склон | `MountainSlope` | светло-серый `0.58, 0.58, 0.60` | да | да | руды (тот же массив, что вершина) | `amb_mountain` |

`IsMountain` = peak **или** slope. Связные куски peak+slope получают один `mountainId` (flood fill 4-соседей).

На миникарте / HUD биомы схлопываются в 4 подписи: лес, поле, гора, вода. Woodland рисуется как лес, Beach — как вода.

## 4. Как собирается карта биомов

Две фазы. **Фаза A** фиксирует ландшафт и больше его не переписывает. **Фаза B** (жилы) читает уже готовые клетки.

Внутри фазы A океан красится первым. Гора и озеро — не цепочка `if`, а семена + совместный BFS: побеждает больший `mScore` / `lScore`. Склон, пляж, растительность кладутся только на ещё не занятое поле.

### 4.1 Океан по краю

Для каждой клетки:

```
edge = min(x, z, width-1-x, height-1-z)     // расстояние до края карты
wobble = (Perlin(x*0.08, z*0.08) - 0.5) * 4  // примерно −2…+2
если edge + wobble < oceanWidth  → Ocean
```

| Параметр | Дефолт | Смысл |
|---|---|---|
| `oceanWidth` | **6** | кольцо океана в клетках |
| `seedOff` | `seed * 17.13` | сдвиг шума |

Кольцо узкое специально: суши должно хватать на поиск руд. Визуальный океан за горизонтом — это pad оверлея (280 м), не игровые клетки.

Старый сейв посреди океана: `NearestWalkable` выталкивает к ближайшей не-океан клетке (озеро тоже ок).

### 4.2 Гора и озеро вместе

Шумы те же (`LakeNoise`, `MountainNoise`), но клетка не красится по порядку проверок.

```
mScore = MountainNoise - mountainPeakThreshold (0.66)
lScore = LakeNoise - lakeThreshold (0.74)
```

1. Семена — локальные максимумы **выше порога** (настоящий пик/озеро), шаг 28 / 18, не больше 5 гор и 8 озёр.
2. Клетка не может быть и горой, и озером: гора берёт `mScore ≥ lScore`, озеро — только если `lScore > mScore + 0.08`.
3. От семян BFS: гора растёт, пока `MountainNoise ≥ 0.60` **и** она владеет клеткой; озеро — пока `LakeNoise ≥ 0.68` и выигрывает с запасом.
4. Озёрное семя не ставится ближе 10 клеток к горному.
5. Массив меньше `mountainMinCells` (24) или `lakeMinCells` (20) откатывается в поле.
6. Если горных клеток после склона мало (`minMountainCapableArea` = 120) — другой внутренний offset шума, тот же сид мира.

Пик и озеро после этого шага больше никто не переписывает.

### 4.5 Постобработка склонов

Кольцо вокруг каждой вершины шириной `mountainSlopeWidth` (**4** клетки, квадрат Чебышева).

Не переписываются: Ocean, Lake, MountainPeak.

На этом шаге вокруг пика ещё поле — склон пишется только на него.

### 4.6 Постобработка пляжей

Кольцо вокруг **озера** шириной `beachWidth` (**2** клетки).

Не переписываются: Lake, Ocean, MountainPeak, **MountainSlope**.

**Пляж есть только у озёр.** У океана берег может быть полем, лесом или горой напрямую — отдельного морского пляжа нет.

### 4.7 Растительность: лес / редколесье / поле

После склона и пляжа оставшееся **поле** красится `VegNoise` (без warp):

| Условие | Биом |
|---|---|
| `veg > forestThreshold` (0.58) | Forest |
| `veg > woodlandThreshold` (0.34) | Woodland |
| иначе | Field |

`VegNoise`: `0.04` × 0.65 + `0.11` × 0.35.

### 4.8 Идентификаторы гор

Flood fill по `IsMountain`. Каждый связный кусок peak+slope получает `mountainId`. Мелкие огрызки почти не появляются: их отсекает рост семени, а не фильтр «≥ 8» у жил.

## 5. Правила биома для геймплея

| Правило | Кто смотрит |
|---|---|
| Вода = Lake или Ocean → нельзя строить | `WorldBiomeMap.CanBuild` |
| Насос (`requiresWater`) — все клетки footprint вода | `WaterExtractor` + `BuildingData` |
| `allowOnWater` — можно на воду | флаги здания |
| Океан блокирует капсулу игрока | `PlayerMovement` / `WorldBiomeMap.BlocksPlayer` |
| Озеро проходимо | то же |
| Экстрактор только на клетку с `ResourceNode` | `PlayerBuilder.NeedsResourceNode` (`id == extractor` или флаг) |
| Нефтянка **не** жила, ставится на сушу куда угодно | `OilExtractor`, `crude_oil` |
| Вода **не** жила, ставится на озеро/океан | `WaterExtractor`, `water` |

Туториал (`Обучение.md`) всё ещё говорит «железо и медь только на `MountainPeak` / `OreAllows`». Это **устарело**: `OreAllows` в коде нет, руда садится на весь горный массив (вершина + склон).

## 6. Какие жилы есть

Жила = объект с `ResourceNode` на **одной клетке**. Запас у всех префабов `infinite = true`. Добыча: `Extractor` в той же клетке вызывает `TryConsume`.

### 6.1 Жилы-ноды (расставляет scatterer)

| Kind в коде | Предмет `ItemData.id` | Префаб | Биом | Подпись на карте | Цвет точки |
|---|---|---|---|---|---|
| `sand` | `sand` | `sand` | Beach | Песок | жёлтый |
| `tree` | `log` | `tree` | Forest, Woodland | Дерево | тёмно-зелёный |
| `iron` | `iron_ore` | `stone_iron_ore` | гора | Железо | красно-коричневый |
| `copper` | `cooper_ore` | `stone_cooper_ore` | гора | Медь | оранжевый |
| `stone` | `stone` | `stone` | гора | Камень | светло-серый |
| `coal` | `coal_ore` | `stone_coal_ore` | гора | Уголь | почти чёрный |
| `sulfur` | `sulfur` | `sulfur` | гора | Сера | жёлтый |

Каталог моделей: `Resources/ResourceNodePrefabs` (`id предмета → префаб`). Слой Unity жил: `RESOURSES`.

Опечатка в id меди (`cooper`, не `copper`) сознательная: так в предметах и префабах.

### 6.2 «Жилы», которых нет как нод

| Ресурс | id | Откуда берётся |
|---|---|---|
| Нефть | `crude_oil` | `OilExtractor` на любой суше. 4 ступени богатства (интервал 2.2 / 1.45 / 0.9 / 0.55 с), запас бесконечный |
| Вода | `water` | `WaterExtractor` только на Lake/Ocean |

Их нет в `Veins`, на карте как руда не рисуются.

## 7. Что такое скопление (кластер) и что такое жила

Три уровня:

```
Биом / горный массив
  └── скопление (cluster): пятно нод одного типа вокруг центра
        └── жила / нода (ResourceNode): одна клетка, один предмет
```

**Жила (нода)** — атомарная точка добычи. Экстрактор 1×1 садится ровно на неё.

**Скопление** — набор нод одного kind в радиусе `clusterRadius` от центра, с зазором `nodeGap` между нодами. Задумано так, чтобы **к каждой ноде можно было подвести ленту**.

Центр скопления запоминается в `clusterCenters` + `clusterKinds` (для руд kind = enum горы, для песка/деревьев −1). Следующее скопление не стартует ближе `clusterGap` (Чебышев) от уже поставленных центров.

## 8. Как расставляются жилы

После готовой карты. Корутина, чтобы загрузка не фризила.

Порядок:

1. Собрать пригодные клетки (гора / пляж / лес)
2. Один список заявок: 5 руд (по `minOresPerType` = 2), песок 2–3, деревья пропорционально лесу
3. Для каждой заявки найти центр с общим `clusterGap`, при неудаче зазор /2
4. Вырастить пятно BFS от центра (`clusterRadius`, `nodeGap`)
5. Горы без единой ноды — добить
6. Восстановить сохранённые жилы под экстракторами (если Regen Map)
7. Перебиндить экстракторы
8. Спрятать меши, оставить stub
9. `WorldMapUI.Rebuild()`

### 8.1 Общие числа (Inspector `WorldResourceScatterer`)

| Поле | Дефолт | Роль |
|---|---|---|
| `nodesPerCluster` | **16** | цель нод в скоплении |
| `clusterRadius` | **10** | Чебышев-радиус пятна |
| `nodeGap` | **2** | мин. зазор нода↔нода (соседи 8 клеток свободны) |
| `clusterGap` | **12** | мин. зазор центр↔центр (песок и горы) |
| `treeDeposits` | **12** | скоплений деревьев в лесу |
| `sandDeposits` | **3** | затем `Clamp(2, 3)` → всегда **2 или 3** пятна песка |
| `minOresPerType` | **2** | жёсткий минимум скоплений каждой руды |
| `ironDeposits` … `sulfurDeposits` | 3 | исторические поля, квота идёт из `minOresPerType` |

`nodeGap = 2` → Чебышев ≥ 2, диагональные соседи тоже запрещены. Между двумя жилами всегда есть клетка под ленту.

### 8.2 Единый проход пятен (`PlaceAllPatchesRoutine`)

Руда, песок и дерево — одинаковые заявки с разным предикатом клетки. Центры всех типов сразу держат общий `clusterGap` (дефолт 12, деградация /2).

| Что | Пригодная клетка | Скоплений | minPick |
|---|---|---|---|
| 5 руд | гора (пик или склон) | по 2 | 3 → 1 |
| Песок | пляж | 2–3 | 5 → 1 |
| Дерево | лес / редколесье | `Clamp(клетки/250, 8…28)` | 5 → 1 |

Пятно растёт BFS от центра, не «перемешать все клетки биома». Не набрало минимум — центр свободен, заявка пробует другую клетку.

Поле, озеро, океан жил не получают. Одна гора может держать несколько типов — это уже не «один тип на массив». Гора без нод добивается в конце.

## 9. Как выглядит одна нода в мире

`SpawnNode`:

1. Мировая точка = центр клетки, Y с `terrain.SampleHeight` (даже если Terrain выключен, heightmap ещё читается).
2. Поворот yaw = 0/90/180/270.
3. Создаётся **stub** (пустой GO + `ResourceNode` + предмет с префаба). Сразу регистрируется в словаре клеток.
4. Меш префаба **не** инстанцируется сразу.
5. В список `Veins` пишется метка для карты.

Стриминг картинки:

- радиус = `GameSettings.RenderDistance` (16–140 м, дефолт 32);
- в радиусе меш поднимается пачками по **6 за кадр**;
- ушёл игрок — меш уничтожается, stub и добыча остаются;
- экстрактор биндится по клетке, качает и вдали.

## 10. Кто ещё читает биомы и жилы

| Система | Зачем |
|---|---|
| `WorldMapUI` | пиксельная копия `BiomeTexture` + цветные точки `Veins`; тултип клетки = подпись жилы |
| `MapExploration` | туман исследования по клеткам, не по биомам |
| `GameAudio` | кроссфейд амбиента по окрестности  (лес / поле / гора / вода) |
| `TutorialFx` | жёлтая подсветка ближних жил нужного типа |
| `PlayerBuilder` | вода / жила для призрака |
| `LoadingScreen` | этапы «биомы» → «жилы» (`ScatterProgress`) |
| `RuntimeMaterials` | материал оверлея, туман земли `_WalkUvFog` |

Жилы в JSON сейва **нет**. Сид мира есть (`SaveData.seed`). Сменишь алгоритм при том же сиде — старые заводы останутся, а руда под ними может уехать (кроме команды Regen с keep).

## 11. Чего система сознательно не делает

- Нет нефти-жилы, нет «нефтяных пятен» на карте.
- Нет жил в поле, на озере, в океане.
- Нет морского пляжа (пляж только вокруг озёр).
- Нет конечного запаса (все ноды infinite).
- Нет сохранения раскладки жил — только сид.
- Поля `ironDeposits` / `copperDeposits` / … в инспекторе не крутят квоту (крутит `minOresPerType`).
- Высота terrain почти не влияет на биом: биом — 2D-шум по клеткам, не heightmap. Горы визуально плоские (цвет клетки), не 3D-рельеф.

## 12. Расхождения vault / туториала / кода

Иметь в виду при переработке, чтобы не опираться на мёртвые формулировки.

| Документ | Утверждение | Факт в коде |
|---|---|---|
| `Обучение.md` | железо и медь на `MountainPeak`, есть `OreAllows` | `OreAllows` нет; руда на любой горной клетке, несколько типов на одной горе можно |
| Inspector deposits | `ironDeposits = 3` и т.д. | квота из `minOresPerType` (2) |
| Карта HUD | «лес / поле / гора / вода» | Woodland=лес, Beach=вода, peak и slope не различаются |

Vault-карточки, которые остаются каноном по смыслу: `WorldBiomeMap.md`, `WorldResourceScatterer.md`, `ResourceNode.md`.

## 13. Зацепки для переработки

Если менять генерацию, эти контракты лучше не ломать молча:

1. **Сид мира** → детерминированная карта. Игрок ждёт «тот же сид = похожий ландшафт».
2. **Клетка жилы** = клетка экстрактора. Размер экстрактора 1×1.
3. **Зазор нод ≥ 2** — лента между жилами.
4. **Все пять руд должны находиться** — обучение и ранний крафт завязаны на `iron_ore` / `cooper_ore`.
5. `Veins` и `TryGetVeinLabel` кормят карту.
6. Stub + стриминг меша — иначе тысячи деревьев убивают FPS.
7. Regen Map keep: BFS по 8-соседям того же `ItemData` от клетки экстрактора.
8. Вода: озеро ходят, океан нет; насос на оба.
9. Нефть пока «ставь где хочешь на суше» — если появятся нефтяные пятна, это новый тип, не `ResourceNode` камня.

Полезные публичные API карты, которые scatterer уже использует:

- `Get(cell)` / `IsWater` / `IsOcean` / `IsLake` / `CanBuild`
- `IsMountain` / `GetMountainId` / `MountainCount` / `CollectMountainCells`
- `CollectBiomeCells`
- `CellWorld` (высота с terrain)
