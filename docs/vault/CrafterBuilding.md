# CrafterBuilding

**Файл:** `Assets/Script/Core/Buildings/CrafterBuilding.cs`  
**Предок:** [[BuildingBase]]  
**Договор:** [[IInteractable]]

## Зачем нужен

Любой станок с рецептом: плавильня, сборщик, химия, нефтепереработка.

Каждый кадр:

1. Есть рецепт? Хватает входов? Есть место на выходе?
2. Если да — крутится прогресс и играет луп [[GameAudio]].
3. Прогресс дошёл до «нужного времени» (рецепт × множитель [[Economy.CraftTimeMul]] / скорость уровня) — забрать ингредиенты, выдать продукты, обнулить прогресс.

## Связи

## Поля

- `currentRecipe` — какой рецепт выбран
- `craftProgress` — сколько «работы» уже сделано
- `inputBuffer` — склад ингредиентов внутри станка
- `level` — 1 или 2 (уровень 2 обычно ×2 скорость)
- `CraftSpeed` — 1 или 2
- `CanUpgradeBuilding` у базы крафтера **false**. Апгрейд только у [[Assembler]] (и у [[Extractor]] отдельно), после своего исследования.

## Методы

### GetEffectiveCraftTime
Сколько секунд займёт один крафт с учётом замедления экономики и скорости уровня.

### Update
Звук лупа. Если нет рецепта/входов/места — стоп. Иначе капает прогресс. При готовности `TryCraft`.

### TryReceiveItem
Принимает только то, что есть во входах текущего рецепта, и только пока буфер не больше «двух крафтов вперёд».

### TryCraft
Проверяет ингредиенты ещё раз, вычитает их, создаёт выходы через `TryOutputToAny`, пишет статистику.

### Interact
Открывает [[MachineUI]] для этого здания.

### WriteSave / ReadSave
Рецепт, прогресс, содержимое входа. Прогресс не может быть больше нового «нужного» времени.

Апгрейд здания: `TryUpgradeBuilding` ставит уровень 2 только если `CanUpgradeBuilding` (у большинства станков нет).
