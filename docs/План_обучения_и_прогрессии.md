### 0.4 Модели зданий: входы/выходы

Как устроено: тело модели — из `wi_models.py` (OBJ в `Resources/Models`), а **плашки портов** (`port_in` / `port_out` / `port_fluid`) ставятся в рантайме по реальным сокетам (`BuildingRestyle.AddPorts`). То есть «у модели 1 вход» может быть по трём разным причинам — чинить надо в разных местах.

| Здание | Сокеты в префабе | Входов нужно по рецептам | Что подозрительно |
|---|---|---|---|
| Конструктор 2×2 | 2 входа (зад, правый бок), 1 выход | 2 | В **теле** модели нарисованы только ворота спереди (выход). Входы — только маленькие плашки на земле, правый бок закрыт стойками крана. Визуально читается как «вход один». |

| Плавильня, Сборщик, Генератор | 1 вход | 1 | ок |

## 1. Принципы нового обучения

1. **Сначала результат, потом правила.** Через 2 минуты игры игрок должен увидеть, как руда едет по ленте и что-то происходит. Всё остальное — потом.
2. **Одна новая вещь за шаг.** Один шаг = одно действие + одна клавиша. Если в тексте два «и» — это два шага.
3. **Показывать, а не писать.** У каждого шага есть подсветка в мире *или* в UI (стрелка, призрак, пульс). Текст — 1 строка, максимум 2.
4. **Учить тогда, когда нужно.** Копирование — когда игроку надо сделать вторую такую же линию. Сплиттер — когда понадобилось разделить поток. Инвентарь — когда хотбар закончился. Это и есть «обучение по ходу игры».
5. **Никаких мёртвых машин.** Построил — работает. Если не работает — машина сама говорит почему.
6. **Каждый этап — награда.** Звук, вспышка, всплывашка «Открыто: …», немного монет.
7. **Обучение не заканчивается — оно переходит в «Цели».** После вводной главы игрок всегда видит следующую цель и путь к ней.

## 2. Новая структура: 3 слоя

```
Слой A  Вводная глава (≈8–10 мин, обязательная, но пропускаемая)
        → один ровный путь: руда → лента → лаборатория → плавильня → слиток

Слой B  Цели / вехи (вся игра)
        → журнал целей с подзадачами, всегда 1 активная цель в углу экрана

Слой C  Контекстные подсказки «в первый раз» (вся игра)
        → короткая подсказка в момент, когда игрок впервые сталкивается с механикой
        → все прочитанные подсказки лежат в «Справочнике», можно перечитать
```

## 4. Слой B — Цели (вехи) на всю игру

### 4.1 Механика

## 6. Карта производства («что из чего, где, на чём, как подключить»)

### 6.1 Что это

Отдельный экран (клавиша **K**, кнопка в трекере целей, кнопка в окне любого станка, клик по любой иконке предмета в игре). Вместо вкладки «Рецепты» в лаборатории (её оставить, но с кнопкой «Открыть карту»).

Три режима в одном окне:

**A. Граф «вся индустрия»** — слева направо по глубине (столбцы 0–7 из таблицы в 0.3):
- узел = предмет (иконка + имя), под ним — иконка станка, где делается (или кирки/вышки — где добывается);
- стрелки = ингредиенты, подпись «×2»;
- цвет состояния: **открыто и производится** (яркий) · **открыто, но не производится** (обычный) · **закрыто** (тусклый, с замком и названием исследования, которое откроет);
- фильтр: «показать только путь к выбранному», «скрыть закрытое»;
- тот же навигатор, что в дереве исследований (`ResearchTreeNav` — пан/зум уже есть).

**B. «Как сделать X»** (открывается кликом по узлу) — дерево вниз до руды:
```
Печатная плата  ×1  ← Конструктор (2 с)        [вход A] [вход B]
├── Кремний ×2      ← Плавильня (1 с)
│   └── Песок ×6    ← Экстрактор на песок   📍 ближайший: 240 м, на север  [Показать на карте]
└── Провод ×4       ← Сборщик (1 с)
    └── Медный слиток ×8 ← Плавильня
        └── Медная руда ×8 ← Экстрактор   📍 120 м
```
- для каждого шага: станок, время, **сколько станков нужно** для выбранной скорости («хочу 1 плату / 2 с» → 1 конструктор, 1 плавильня кремния, 2 сборщика провода…);
- для закрытых шагов: «Нужно исследование: Кремний (480 песка)» → кнопка «Открыть в дереве»;
- кнопка **«Отслеживать»** → цепочка попадает в трекер целей (слой B) как пользовательская цель с галочками по мере того, как игрок ставит станки.

**C. «Как подключить»** (вкладка у каждого станка в режиме B):
- вид сверху на клетки станка: где вход(ы), где выход, стрелками; пример: лента с кремнием → вход A, лента с проводом → вход B, выход → дальше;
- текст: «Ингредиенты можно подавать в любой вход» (так работает `CrafterBuilding`), «Жидкость — только трубой во вход с синей плашкой»;
- кнопка «Показать призрак» → в мире у выбранного станка рисуется призрачный маршрут (механика из 3.2 п.3).

### 6.2 Данные

- Строится **автоматически** из `GameDatabase` (рецепты, исследования, `RecipeCodex.ExtractTable`) — ничего руками не заполнять.
- Глубина предмета = 0 для сырья, иначе 1 + max(глубина ингредиентов) по самому раннему рецепту.
- «Где добывается»: перенести `ExtractTable` в данные `ItemData` (`extractedBy`, `biomes`), чтобы карта и подсказки брали оттуда, а не из массива строк в коде.
- Ближайшая жила: `WorldResourceScatterer.Veins` + `TutorialSystem.CollectVeinCells` (уже есть) → дистанция и направление.

### 6.3 Где карта встречается в игре

- клик по иконке предмета **где угодно** (рецепт станка, цена исследования, трекер, склад) → карта на этом предмете;
- в узле дерева исследований: «Что нужно сдать» → каждый предмет кликабелен → «Как сделать»;
- в окне станка при выборе рецепта: под рецептом строка «Ингредиенты: Кремний ← Плавильня, Провод ← Сборщик» + «Подробнее».

### 6.4 Диаграмма «2 входа» (для Конструктора, Химзавода)

Картинка в подсказке и в режиме C: квадрат станка, 2 стрелки внутрь разного цвета с иконками ингредиентов, 1 стрелка наружу. Те же цвета — на плашках портов в мире (см. 7.3), чтобы картинка и модель совпадали.
